# NewsFlow 固定 ECS 站点

用户要求把已有新闻工具部署为固定公网站点，并明确允许复用本机 ThinkFlow 的服务器连接。实际只读检查已确认：ECS 为 Ubuntu 24.04、47.115.130.110，Nginx 在 80 端口运行，ThinkFlow 在本机 8000 端口运行；已有连接及已记录的主机密钥验证成功。约 1 GiB 内存可用。

继续使用现有新闻界面、43 个频道、本地分类模型和按浏览器保存的收藏、纠错与来源偏好。固定入口选择 `https://47.115.130.110/newsflow/`，HTTP 同路径保留，不占用 ThinkFlow 原来的 HTTP 根路径，也不依赖临时隧道域名。官方已确认 2026 年 1 月正式开放短期 IP 证书，因此当前通过 Let's Encrypt `shortlived` profile 和 Certbot 5.9.0 提供可信 HTTPS，不需要先购买域名；专用 systemd timer 每天两次检查续期。

Nginx 只提供生成的公开页面和数据，不暴露下载版的共享写入接口。程序放在 `/opt/newsflow`，公开站点放在 `/var/lib/newsflow/site`。新闻更新使用专门的非 root 用户，由 systemd oneshot 服务和开机启用的 timer 调度；一轮结束后 120 秒再次执行，单轮耗时会影响实际间隔。页面仍每 20 秒检查已发布数据。

更新程序先完成抓取与分类，然后原子替换新闻 JSON；更新不重写网页资源。进程异常、分类失败或磁盘写入失败不能损坏上一份数据。来源失败继续使用七天内缓存，日期不明不伪造发布时间，仍保留最多 1,000 条、最多 128 个来源与现有公网地址抓取保护。初次安装可以使用随源码提供的公开快照，随后的真实抓取更新它。

Pages 继续支持原来的 300 秒调度提示；ECS 页面及客户端从公开数据中的部署类型和间隔显示正确的 120 秒说明。旧快照没有部署字段时按 Pages 兼容。收藏仍按浏览器和站点来源保存，不在两个网址间自动同步。

服务器变更新增 NewsFlow 文件、用户、虚拟环境、systemd 单元、Nginx location include 和独立 HTTPS server；先备份现有 Nginx 配置，语法检查成功后平滑 reload。证书账户、私钥与客户端位于项目外。无需停止或重启 ThinkFlow，不修改其账号、数据、密码、API 配置或已有隧道。更新任务限制为一个 CPU 和 700 MiB 内存，自动新闻不调用付费 API。

验收需要完整 Python/Node 检查、Linux systemd/Nginx 配置校验、至少一次真实更新、固定入口和静态资源 HTTP 200、可信 IP HTTPS 与完整续期演练、43 个来源、Edge 桌面与手机使用、收藏与刷新保留，以及 ThinkFlow 健康接口持续 200。最后保存部署说明、源码和验收记录到现有 GitHub 仓库。服务器重启不作为测试，以免打断已有站点；开机启用状态与服务执行单独验证。
