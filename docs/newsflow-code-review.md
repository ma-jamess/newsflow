# NewsFlow 1.4 最终代码复核

复核日期：2026-10-31。独立复核者：`/root/newsflow_final_review`。
复核覆盖新闻读取、缓存与更新协调、HTTP 接口、新闻界面和完整源码包；以设计文档和实施计划为依据。

## 结果与修复

没有发现 Critical 问题。两个 Important 问题已修复，并各用两个回归测试验证：

1. 收藏或修改类别成功后，之前发出的详情响应仍可能覆盖界面的新状态。成功写入现在会使旧详情请求失效，并重新读取所选文章。测试覆盖收藏和人工改类两种乱序。
2. 新闻源首次读取的旧响应可能撤销已完成的启停或隐藏新增订阅。现在使用读取代次和进行中的写入计数，忽略旧响应，写入完成后读取最新来源。测试覆盖启停和添加。

以上四个前端回归测试均在修复前失败、修复后通过。最终复核后的全量验证还发现一处 Windows HTTP 断连：拒绝请求时未读取请求体，关闭连接会偶发丢失错误响应。
先读取上限为 8 MiB 的请求体，再检查来源、令牌和媒体类型，随后才解析 JSON 和处理业务。
新增三个真实 HTTP 回归场景，每个连续提交 25 次 1 MiB 请求：无效令牌、跨来源、错误媒体类型。
三个场景修复前均出现连接中断，修复后均返回完整的 403/415 JSON，且没有保存新闻。

最终 Python 测试 **79/79**，Node 测试 **30/30**；JavaScript 语法与 `git diff --check` 通过。
Python 有一条现有第三方 pytz 的弃用警告，不影响运行。
独立复核者另外验证了当时的 76 项 Python、26 项 Node 和候选包的 118 条文件哈希；最终包的校验报告独立放在 `dist` 中，不把包自身的哈希写进包内。

## 暂缓的小问题

`LiveNewsUI.fullTime()` 暂未显示年份，较早收藏的日期可能不够明确。新闻排序与缓存中的完整时间戳仍正常。

## 范围判断

- 既有 DeepSeek 内部实现与模型选择属于此前 1.3 工作；本次保留手动单条入口。自动新闻与批量处理不调用付费接口，复核与界面写入测试使用禁用的付费提供方。
- 现有固定测试集指标用于毕设实验，不能推断当前新闻准确率或五类外识别效果。实时数据验证只证明来源有近期内容、更新成功和应用可用。
- 本版通过源码包让其他人安装自己的本机实例，服务监听 `127.0.0.1`。多人共享站点的账号与权限不属于这次交付，不能把本机令牌机制当作托管网站的账号系统。

改动保留在原有功能分支，未提交或发布 GitHub。原 1.3 修改与编辑前快照保留。
