# 从其他两个项目借鉴的做法

依据老师对垃圾识别和流浪猫狗识别项目的要求，比较可以迁移到新闻分类的做法。当前没有这两个项目的完整源码或实验文件，所以不评价其真实准确率，也不声称审查了它们的实现。

| 其他项目要求 | 新闻分类可以怎么做 | 当前落实 |
| --- | --- | --- |
| 讲清类别编号与标注 | 说明 class.txt 索引如何经过 LABELS 映射为五类中文标签 | 数据与源码说明保留实际映射 |
| 分清 GPU 与 CPU 训练 | 说明 scikit-learn CPU 计算，threadpool_limits 控制 CPU 线程，不是 GPU 开关 | 模型报告列出 CPU 方案 |
| 分清 best 与其他模型文件 | 说明 models.joblib 包含三套模型，report 指定默认方案 | 独立模型报告与容器说明 |
| 指出训练和预测入口 | 分开 train.py、verify_models.py、run.py 与 ECS 更新脚本 | 源码运行说明 |
| 每个模型有验证报告 | 提供各方案选参、矩阵、指标、错误及限制 | 三模型可读报告和复核脚本 |
| 界面“建议”要可追溯 | 核对提示来自阈值规则；文字线索来自特征与权重差 | 分类与核验说明 |
| 只识别猫狗和坐标功能过浅 | 保留订阅采集、分类、阅读筛选、人工核验和持久化的实际流程 | 不退回只有输入框和类别输出的页面 |
| 旧成果找不到仍保留取数方法 | 来源目录、抓取入口、固定数据版本和源码交付独立保存 | 来源清单、manifest、GitHub 和完整包 |

不引入 YOLO、CAM、BiFPN、目标框或轨迹坐标来装饰新闻分类。它们解决的任务不同，现有新闻代码没有实现这些模块。文档中未确认的语音转写不作为本项目模块定义。

优先改进是把已有成果变得可核对：模型报告下载、完整工程说明、真实新闻判定案例、保存验证和可复现测试。新增算法或更多功能应在这些基础清楚以后进行。
